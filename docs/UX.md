# UX-дослідження та проєктування сервісу «Dragon Food»

## 1. Персони користувачів

### Персона 1: Богдан, 20 років — студент університету
* **Пристрій:** Смартфон (Android/iOS, ширина екрана 360–390 px), інколи ноутбук.
* **Контекст:** Замовляє їжу в гуртожиток або додому між парами чи під час підготовки до іспитів.
* **Цілі:** Швидко знайти ситний обід (бургери, піцу, суші) з недорогою або безкоштовною доставкою та оформити замовлення за 1–2 хвилини без реєстрації.
* **«Болі»:** Довгі форми оформлення, незрозуміла підсумкова вартість доставки до моменту чекауту, дрібні кнопки на мобільному екрані, неможливість швидко додати кілька однакових позицій (наприклад, 3 бургери на компанію).

### Персона 2: Ростік , 32 роки — менеджерка проєктів (працює віддалено)
* **Пристрій:** Ноутбук (Desktop 1440 px) у робочий час та смартфон увечері.
* **Контекст:** Замовляє обід додому або вечерю для сім'ї після робочого дня.
* **Цілі:** Обрати перевірений заклад з високим рейтингом, зручно переглянути склад страв, вказати точні деталі адреси (під'їзд, поверх, чи працює домофон), щоб кур'єр не телефонував зайвий раз під час робочих дзвінків.
* **«Болі»:** Відсутність поля для вказівки наявності домофону, перевантажений банерами інтерфейс, відсутність темної теми при замовленні ввечері.

## 2. User Stories
1. **Як голодний користувач**, я хочу бачити категорії кухні та пошук на головному екрані, щоб за кілька секунд знайти потрібний тип їжі.
2. **Як користувач каталогу**, я хочу фільтрувати заклади за категорією та сортувати за часом доставки або рейтингом, щоб обрати найшвидший або найкращий ресторан.
3. **Як клієнт ресторану**, я хочу додавати страви в кошик і змінювати їх кількість кнопками `+` та `-` (до 10+ порцій), щоб легко сформувати замовлення на себе або компанію.
4. **Як замовник доставки**, я хочу оформити замовлення у зручному центральному модальному вікні з вказівкою вулиці, будинку, квартири та перемикачем домофону «Так/Ні», щоб кур'єр доставив їжу без зайвих уточнень.
5. **Як користувач мобільного браузера**, я хочу мати адаптивний інтерфейс із великими закругленими кнопками та зручним кошиком, щоб комфортно користуватися сайтом однією рукою.

## 3. Сценарій користувача (User Flow головного сценарію)
`Вхід на Головну (/)` → `Клік на категорію (напр. «Бургери») або кнопку «Переглянути заклади»` → `Каталог закладів (/restaurants)` → `Пошук / фільтрація закладів` → `Вибір ресторану` → `Сторінка меню закладу (/restaurants/:id)` → `Додавання страв у кошик (+1, +2...)` → `Відкриття кошика (Cart Drawer)` → `Натискання «Оформити замовлення»` → `Центральне модальне вікно чекауту` → `Заповнення адреси (вулиця, кв., домофон Так/Ні) і телефону` → `Валідація форми` → `Підтвердження та екран успішного замовлення`.

## 4. Карта сайту (Sitemap)
* **Головна (`/`)**
  * **Каталог закладів (`/restaurants`)**
    * **Меню закладу (`/restaurants/:id`)**
      * *Виїжджаючий кошик (Cart Drawer)*
      * *Центральне модальне вікно оформлення замовлення*
  * **Оформлення замовлення (`/checkout`)** — окрема сторінка для прямого переходу та безбар'єрного доступу.
  * **Керування закладами та контакти (`/manage`)** — форма додавання закладу/страви та зворотного зв'язку.
  * **Сторінка помилки (`404`)**
